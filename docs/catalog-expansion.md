## Safe installation

This batch originally brought fresh seeds to 50 tracks; the later addition brings current fresh seeds to 70. For an existing catalog:

```sh
npm run catalog:expand-demo
# Or after rebuilding Docker:
docker compose exec api npm run catalog:expand-demo
```

The addition transaction writes genres, artists, albums, songs and durable outbox tasks together. It preserves existing songs, user accounts, follows, playlists and listening sessions. It adds genre memberships to reused curated artists, without merging arbitrary imported artists by name. Conflicting video IDs or retired records abort the transaction. A second run performs no changes. The legacy `catalog:refresh-demo` command still handles only its original 15-song migration; it is separate from this addition.

The live run inserted 13 genres, 52 artists, 35 single releases and 35 songs, and updated the genre memberships of two existing artists. Checksums verified that users, follows, playlists and playback sessions were unchanged by the catalog migration. Fictional database fixtures remain exactly 808 domain records / 228 nodes / 1,260 relationships.

Genre browsing now queries the whole catalog instead of filtering only the first 15 records. All genre chips are reachable, and language filtering includes Instrumental and Undetermined.

## Demo usage

`npm run demo:simulate` is an **opt-in, roughly ten-minute** browser demonstration. It signs in as `listener@resonance.local`, saves Electronic Rock and Chill as favorite genres, follows Clarx and Beave, and creates a dated “Rock & unwind” playlist. It completes selected tracks, samples others and skips a few outside the preference profile. Playback uses real elapsed time, the visible official YouTube player, normal REST sessions, ten-second checkpoints and ordinary UI actions. It never injects fabricated listening totals or rewrites existing history.

Personalization in this application combines explicit favorite genres, artist follows and similar listeners. Listening also excludes already-heard tracks and updates graph affinities. The demonstration uses **preferences plus follows plus listening**; it does not claim that listening alone automatically rewrites the user's saved favorite genres.

The simulation writes before/after recommendation data, session IDs and checkpoints to `tmp/demo-listener-simulation.json`, and a screenshot to `tmp/demo-listener-recommendations.png`. It asserts that all five leading recommendations match the chosen genres. It retains existing unrelated follows and history. Re-running adds another real listening session sequence, so run it deliberately.

```sh
# Separately verify all 35 new tracks in the admin demo account:
PLAYBACK_CHECK_EMAIL=admin@resonance.local npx tsx scripts/check-demo-playback.ts --additions
# Apply the listening demonstration to the demo listener:
npm run demo:simulate
```

Provider checks are point-in-time local checks, not permanent availability guarantees. No YouTube Data API key is needed for these curated links and playback checks.
